## 1.3 Принципы разделения

### Telegram Bot — "оперативный пульт"
- Все push-коммуникации идут через бот.
- Inline-кнопки для быстрых действий (Принять / Отклонить / Перенести / Эскалация).
- Минимальный ввод данных (reply-сообщения с числом/фото).
- Deep-link для перехода в Mini App с контекстом (`?task_id=123&view=plan_fact`).

### Telegram Mini App — "рабочее место"
- Полноценный SPA внутри Telegram (React + Telegram Web Apps SDK).
- Табличные формы ввода (план-факт, объёмы).
- Визуализация (Гант, канбан, графики накоплений).
- Работа с документами и медиа.
- Responsive: адаптация под мобильный экран Telegram.

### Backend — "ядро системы"
- Единая точка правды для данных и бизнес-логики.
- REST API для Mini App, Webhook handler для Bot.
- RBAC enforcement на уровне API.
- AuditLog для всех мутаций.
- Job-очередь для отложенных задач (уведомления, эскалации, отчёты).
- ETL-пайплайн для импорта Excel-файлов.

## 1.4 Коммуникация между компонентами

| Связь | Протокол | Описание |
|-------|----------|----------|
| Telegram → Bot Backend | Webhook (HTTPS) | Telegram отправляет updates на endpoint |
| Bot Backend → Telegram | Bot API (HTTPS) | Отправка сообщений, inline-кнопок |
| Mini App → Backend API | REST (HTTPS) + WebSocket | CRUD-операции, real-time обновления |
| Backend → PostgreSQL | TCP (pg driver) | Персистентное хранение |
| Backend → Redis | TCP | Очереди (BullMQ), кэш, сессии |
| Backend → S3/MinIO | HTTPS | Файловое хранилище |
| Cron/Jobs → Backend | In-process (BullMQ workers) | Scheduled + event-driven задачи |
