# 2. Workflow Logic

## 2.1 Основные рабочие процессы (цепочки)

Система поддерживает следующие ключевые workflow-цепочки, извлечённые из ТЗ и структуры Excel-файлов.

### Workflow-таблица

| # | Workflow | Стадии (State Machine) | Триггер входа | Триггер перехода | Ответственные роли | Сроки / SLA | Эскалация |
|---|----------|----------------------|----------------|------------------|-------------------|-------------|-----------|
| WF-01 | **Ежедневный план-факт** | `PLAN_SET → FACT_ENTRY → REVIEW → CLOSED` | `SCHEDULE` (начало рабочего дня) | `UI_ACTION` (ввод факта, подтверждение) | Прораб → Начальник участка → Руководитель проекта | План — до 08:00; Факт — до 18:00; Ревью — до 20:00 [Assumption] | Нет факта до 19:00 → уведомление начальнику участка; до 21:00 → руководителю проекта |
| WF-02 | **Жизненный цикл задачи (TaskInstance)** | `CREATED → ASSIGNED → IN_PROGRESS → DONE → VERIFIED` | `IMPORT` (из шаблона при создании проекта) или `UI_ACTION` | `UI_ACTION` (назначение, старт, завершение, приёмка) | Прораб → Исполнитель → Прораб → Начальник участка | Зависит от TaskTemplate.duration_days | Просрочка > 1 дня → прораб; > 3 дней → начальник участка; > 7 дней → руководитель проекта [Assumption] |
| WF-03 | **Модуль: производство → монтаж** | `PLANNED → IN_PRODUCTION → PRODUCED → SHIPPED → ON_SITE → MOUNTED → INSPECTED` | `IMPORT` (план модулей) | `UI_ACTION` + `DATA_CHANGE` | Производство → Логистика → Монтажная бригада → ОТК | Даты из плана модулей (Дата производства → Дата отгрузки → Дата монтажа) | Просрочка этапа > 1 дня → ответственному; > 3 дней → руководителю проекта [Assumption] |
| WF-04 | **ГПР (график производства работ)** | `DRAFT → APPROVED → ACTIVE → COMPLETED` | `UI_ACTION` (создание ГПР) | `UI_ACTION` (утверждение, активация) | Начальник участка → Руководитель проекта | Утверждение ГПР — 2 рабочих дня [Assumption] | Нет утверждения > 2 дней → эскалация на руководителя проекта |
| WF-05 | **Дефект / Отклонение** | `REPORTED → ASSIGNED → IN_FIX → FIXED → VERIFIED` | `UI_ACTION` (фиксация дефекта через Bot) | `UI_ACTION` (назначение, исправление, проверка) | Прораб / ОТК → Исполнитель → Прораб / ОТК | Критичный — 1 день; Обычный — 3 дня [Assumption] | Просрочка → эскалация по тому же принципу что WF-02 |
| WF-06 | **Импорт Excel (ETL)** | `UPLOADED → VALIDATING → VALIDATED → IMPORTING → COMPLETED / FAILED` | `IMPORT` (загрузка файла) | `DATA_CHANGE` (автоматические переходы) | Администратор / Начальник участка | Валидация — синхронно; Импорт — до 5 минут [Assumption] | Ошибка импорта → уведомление загрузившему + админу |
| WF-07 | **Документооборот** | `DRAFT → ON_REVIEW → APPROVED → ARCHIVED` | `UI_ACTION` (загрузка документа) | `UI_ACTION` (отправка на ревью, утверждение) | Автор → Рецензент → Утверждающий [Assumption] | Ревью — 2 рабочих дня [Assumption] | Нет ревью > 2 дней → эскалация |

## 2.2 Диаграмма состояний — WF-01 (Ежедневный план-факт)

```
                    SCHEDULE (08:00)
                         │
                         ▼
                   ┌───────────┐
                   │ PLAN_SET  │  ← Прораб вводит план на день
                   └─────┬─────┘
                         │ UI_ACTION (ввод факта)
                         ▼
                   ┌────────────┐
                   │ FACT_ENTRY │  ← Прораб/бригадир вводит факт
                   └─────┬──────┘
                         │ UI_ACTION (подтверждение)
                         ▼
                   ┌──────────┐
                   │  REVIEW  │  ← Начальник участка проверяет
                   └─────┬────┘
                    ┌────┴────┐
                    ▼         ▼
              ┌────────┐ ┌──────────┐
              │ CLOSED │ │ REJECTED │ → возврат в FACT_ENTRY
              └────────┘ └──────────┘
```

## 2.3 Диаграмма состояний — WF-02 (Жизненный цикл задачи)

```
     IMPORT / UI_ACTION
           │
           ▼
      ┌─────────┐
      │ CREATED │
      └────┬────┘
           │ UI_ACTION (назначение)
           ▼
      ┌──────────┐
      │ ASSIGNED │
      └────┬─────┘
           │ UI_ACTION (принятие исполнителем)
           ▼
    ┌─────────────┐
    │ IN_PROGRESS │
    └──────┬──────┘
           │ UI_ACTION (завершение)
           ▼                        ┌──────────┐
      ┌──────┐                      │ BLOCKED  │
      │ DONE │                      └──────────┘
      └──┬───┘                       (из любого
         │ UI_ACTION (приёмка)        состояния)
         ▼
    ┌──────────┐
    │ VERIFIED │
    └──────────┘
```

## 2.4 Диаграмма состояний — WF-03 (Модуль: производство → монтаж)

```
  IMPORT (план)
       │
       ▼
  ┌─────────┐    UI_ACTION     ┌───────────────┐    UI_ACTION     ┌──────────┐
  │ PLANNED │ ──────────────► │ IN_PRODUCTION │ ──────────────► │ PRODUCED │
  └─────────┘                 └───────────────┘                 └────┬─────┘
                                                                     │
       ┌─────────────────────────────────────────────────────────────┘
       │ UI_ACTION
       ▼
  ┌─────────┐    UI_ACTION     ┌─────────┐    UI_ACTION     ┌─────────┐    UI_ACTION     ┌───────────┐
  │ SHIPPED │ ──────────────► │ ON_SITE │ ──────────────► │ MOUNTED │ ──────────────► │ INSPECTED │
  └─────────┘                 └─────────┘                 └─────────┘                 └───────────┘
```

## 2.5 Правила переходов (Guards)

| Workflow | Переход | Guard (условие) |
|----------|---------|-----------------|
| WF-01 | PLAN_SET → FACT_ENTRY | `plan_day > 0` для хотя бы одной строки |
| WF-01 | FACT_ENTRY → REVIEW | Все обязательные строки имеют `fact_day != NULL` |
| WF-02 | CREATED → ASSIGNED | `assignee_id IS NOT NULL` |
| WF-02 | IN_PROGRESS → DONE | Все зависимые задачи (predecessors) в статусе `DONE` или `VERIFIED` |
| WF-02 | DONE → VERIFIED | Подтверждение от роли с permission `task.verify` |
| WF-03 | PRODUCED → SHIPPED | `shipment_date IS NOT NULL`, документы на отгрузку прикреплены [Assumption] |
| WF-03 | MOUNTED → INSPECTED | Фото-фиксация монтажа загружена [Assumption] |
| WF-04 | DRAFT → APPROVED | Все задачи ГПР имеют `start_date` и `end_date` |
| WF-06 | VALIDATING → VALIDATED | Нет критических ошибок валидации |

## 2.6 SLA и автоматические действия

| Условие | Время | Действие | Тип триггера |
|---------|-------|----------|-------------|
| Факт дня не введён | 19:00 [Assumption] | Напоминание прорабу | SCHEDULE |
| Факт дня не введён | 21:00 [Assumption] | Эскалация начальнику участка | SCHEDULE |
| Задача просрочена | +1 день от deadline | Уведомление исполнителю + прорабу | SCHEDULE |
| Задача просрочена | +3 дня от deadline | Эскалация начальнику участка | SCHEDULE |
| Задача просрочена | +7 дней от deadline | Эскалация руководителю проекта | SCHEDULE |
| Модуль не отгружен | +1 день от plan_shipment_date | Уведомление ответственному за производство | SCHEDULE |
| Документ не согласован | +2 рабочих дня от подачи | Эскалация утверждающему [Assumption] | SCHEDULE |
| Дефект (критический) не исправлен | +1 день от фиксации | Эскалация руководителю проекта | SCHEDULE |
