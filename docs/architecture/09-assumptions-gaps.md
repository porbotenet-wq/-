# 9. Assumptions & Critical Gaps

## 9.1 Сводная таблица допущений

| ID | Категория | Что неизвестно | Допущение для MVP | Как уточнить / проверить |
|---|-----------|---------------|-------------------|-------------------------|
| **ASMP-001** | Пользователи | Конкретные ФИО, Telegram ID ответственных отсутствуют в доступных данных | Поле `telegram_id` обязательно в таблице User. Маппинг при первом входе через `/start`. Admin назначает роль вручную. | Получить список ответственных с TG ID от заказчика. Интегрировать с HR-системой (post-MVP). |
| **ASMP-002** | RBAC Scope | Точная гранулярность scope (по фасаду, по участку, по этажу) не специфицирована | MVP: scope = `project_id` + `facade_ids[]`. Более детальная фильтрация (этаж, зона) — post-MVP. | Согласовать с заказчиком матрицу "кто видит что" на примере СИТИ-4. |
| **ASMP-003** | Документы | Конкретные типы документов и их workflow не описаны в Excel-файлах | Базовый workflow: DRAFT → ON_REVIEW → APPROVED → ARCHIVED. Типы: PHOTO, PDF, DOCX, XLSX, DWG, OTHER. | Собрать реальный документооборот у инженеров ПТО. |
| **ASMP-004** | Время SLA | Точное время напоминаний и эскалаций не зафиксировано в ТЗ | 08:00 (утренний план), 19:00 (напоминание о факте), 21:00 (эскалация факта), 23:00 (сводка). Все настраиваемые. | Согласовать с прорабами и руководителями реальный рабочий график. |
| **ASMP-005** | Зависимости задач | Из Excel-файлов не извлекаются явные зависимости между задачами (нет колонки "предшественники" в ГПР) | Зависимости устанавливаются вручную в UI или при импорте ГПР (если будет добавлена колонка). MVP — без автоматического CPM. | Проверить наличие колонки зависимостей в реальных ГПР. Спросить, нужен ли CPM для MVP. |
| **ASMP-006** | Бригады | Нет справочника бригад в исходных данных. В план-факт "Бригада" — текстовое поле. | MVP: бригада = текстовое поле (VARCHAR). Post-MVP: справочник бригад с привязкой к User. | Получить список бригад и их состав. |
| **ASMP-007** | Связь модуль ↔ СМР | Колонка `Связь СМР` в плане модулей может не содержать прямые FK на задачи | Связь устанавливается вручную или по совпадению кода работы. Если не найдена — NULL. | Проверить формат колонки `Связь СМР` в реальных данных. |
| **ASMP-008** | Выходные/праздники | Нет календаря рабочих/нерабочих дней | MVP: все дни рабочие. Настройка `weekend_notifications = false` отключает уведомления в Сб/Вс. Производственный календарь — post-MVP. | Уточнить график работы на объекте (часто 6/1 или 7/0). |
| **ASMP-009** | Offline-режим | Не описан в ТЗ | MVP не поддерживает offline. При потере связи — показывать предупреждение. | Оценить реальное покрытие связью на объекте. |
| **ASMP-010** | Gantt-библиотека | Не указана конкретная библиотека для диаграммы Ганта | MVP: кастомный компонент на React + SVG (базовый). Если нужен drag-and-drop дат и критический путь — DHTMLX Gantt (коммерческая лицензия). | Согласовать бюджет на лицензии. Определить минимально необходимый функционал Ганта. |
| **ASMP-011** | Фото-фиксация | Требования к обязательности фото при смене статусов (монтаж модулей, приёмка) не детализированы | MVP: фото опционально. Обязательность настраивается per-scenario. | Уточнить у ОТК какие этапы требуют обязательного фото. |
| **ASMP-012** | Уровни эскалации — модули | Точная цепочка эскалации для модулей не описана | Применяем аналогичную задачам: 1 день → ответственный, 3 дня → site_manager, 7 дней → project_director. | Согласовать с производством и логистикой. |
| **ASMP-013** | Множественные проекты | ТЗ описывает один объект (СИТИ-4). Неясно, нужна ли мульти-проектность. | MVP: multi-tenant по project_id. Все сущности привязаны к Project. Но UI оптимизирован под один активный проект. | Уточнить у заказчика: один проект или портфель? |
| **ASMP-014** | Формат кодов работ | Формат `Код работы` может отличаться между файлами (ГПР vs СМР vs Модули) | MVP: коды как текстовые строки. Нормализация при импорте (trim, upper). Маппинг ручной если форматы различаются. | Сверить форматы кодов между всеми Excel-файлами. |
| **ASMP-015** | Reviewer для задач | Роль "проверяющего" (reviewer) для задач не формализована | MVP: reviewer = вышестоящий по иерархии (для foreman → site_manager). Может быть назначен вручную. | Согласовать цепочку утверждения с заказчиком. |
| **ASMP-016** | JWT-параметры | Время жизни токенов не специфицировано | Access token: 15 мин. Refresh token: 7 дней. | Security review. |
| **ASMP-017** | AuditLog retention | Срок хранения аудит-логов не определён | Хранить бессрочно (MVP). Post-MVP: архивация > 1 года в cold storage. | Уточнить требования регулятора / заказчика. |
| **ASMP-018** | Накопительные из Схемы со сводой | Структура time-series (даты как колонки) требует транспонирования при импорте | Импорт транспонирует: каждая дата-колонка → строка AccumulativeSeries (metric, date, value). | Проверить на реальном файле. |
| **ASMP-019** | Phase headers (План запуска) | Формат этапных заголовков ("1-й этап…") не формализован | Распознавание по эвристике: строки без числовых данных в колонках кол-во/даты. | Проверить на реальном файле. |
| **ASMP-020** | Критический порог отклонения | Порог 20% для уведомления о критическом отклонении не зафиксирован в ТЗ | MVP: 20% (настраиваемый параметр `deviation_threshold_pct`). | Согласовать с руководителями проекта. |

## 9.2 Критические разрывы (Critical Gaps)

| # | Gap | Влияние на MVP | Рекомендация |
|---|-----|---------------|-------------|
| CG-01 | **Нет реальных Excel-файлов для тестирования импорта** | ETL может не работать с реальными данными (merged cells, формулы, кодировка) | Получить 3+ реальных файла каждого типа до начала разработки ETL |
| CG-02 | **Нет Telegram Bot Token** | Невозможна разработка Bot-функционала | Создать тестового бота через @BotFather |
| CG-03 | **Нет списка реальных пользователей** | Невозможно настроить RBAC для пилота | Получить список минимум 5-10 пользователей с ролями и TG ID |
| CG-04 | **Нет доступа к реальному объекту для UX-тестирования** | UI может не соответствовать рабочим условиям (размер экрана, перчатки, солнце) | Провести полевой UX-тест на этапе альфа |
| CG-05 | **Не определён хостинг / инфраструктура** | Невозможен деплой | Определить: облако (AWS/Yandex Cloud) или on-premise. Для MVP достаточно VPS 4 vCPU, 8GB RAM. |
